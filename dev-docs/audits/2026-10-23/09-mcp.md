## Confirmed actionable findings

### MCP-001 — P2 — Broker calls change timestamp-shaped string arguments

- Status: new; no matching open MCP serialization item found in TODO.md. Confidence: high; source call chain plus an in-memory probe of the installed Newtonsoft assembly.
- Evidence: `Assets/CoreAIMcp/Runtime/Tools/CoreAiToolsBrokerMcpTool.cs:156-158` parses `arguments_json` with `JObject.Parse`, whose default reader infers dates. The real RPC path uses this parser before queueing (`Assets/CoreAIMcp/Runtime/Tools/McpToolRegistry.cs:99-106`) and forwards the resulting object to the captured tool (`Assets/CoreAIMcp/Runtime/Tools/CoreAiToolsBrokerMcpTool.cs:186`). Direct JSON-RPC intentionally uses `DateParseHandling.None` (`Assets/CoreAIMcp/Runtime/Protocol/JsonRpc.cs:88-90`).
- Trigger/impact: call an echo/string-consuming tool through `coreai_tools` with `arguments_json` equal to `{"echo":"2026-09-08T10:00:00.000Z"}`. The nested value becomes `JTokenType.Date`, and `McpArguments.String` (`Assets/CoreAIMcp/Runtime/Tools/McpArguments.cs:21-24`) returns culture-formatted text instead of the submitted identifier/string. A tool that requires `JTokenType.String` can reject the same value. Direct and broker routes therefore execute different arguments for the same logical request; lean residency makes the affected route the normal one.
- Existing guards/tests: registry argument copying and binding revalidation preserve the already-coerced object; they do not fix it. `Assets/CoreAIMcp/Tests/EditMode/McpRpcDispatcherEditModeTests.cs:318-347` covers timestamp preservation only on direct requests. `Assets/CoreAIMcp/Tests/EditMode/McpDynamicToolsEditModeTests.cs:167-171` and `Assets/CoreAIMcp/Tests/EditMode/McpDynamicToolsEditModeTests.cs:290-302` cover ordinary broker strings, without timestamp values.
- Fix direction: share a single-object JSON reader configured with `DateParseHandling.None` between direct and nested argument parsing, retaining trailing-content/depth checks.
- Regression: dispatch a raw `tools/call` to the broker with nested ISO strings (fractional seconds and nonzero offset); assert both token type and exact text observed by a captured fake tool equal the direct route. Include a strict string-consuming tool and a trailing-content rejection case.

### MCP-002 — P2 — World/log tool failures are returned with `isError: false`

- Status: new defect; existing coverage debt at `TODO.md:2538-2539` already names the affected wrappers. Confidence: high from the complete failure-return path; not runtime reproduced.
- Evidence: `Assets/CoreAIMcp/Runtime/Tools/GetModLogsMcpTool.cs:49-58` and `Assets/CoreAIMcp/Runtime/Tools/WorldCommandMcpTool.cs:52-74` return `new McpToolResult(content)` without mapping the inner failure. Its default `isError` is false (`Assets/CoreAIMcp/Runtime/Protocol/McpContent.cs:65-77`). The dispatcher serializes that result unchanged (`Assets/CoreAIMcp/Runtime/Server/McpRpcDispatcher.cs:184-185`).
- Trigger/impact: `get_mod_logs` with `{"level":"chatty"}` returns `{"success":false,...}` at `Assets/CoreAIMods/Runtime/Logging/GetModLogsLlmTool.cs:100-105` and `Assets/CoreAIMods/Runtime/Logging/GetModLogsLlmTool.cs:130-132`. `world_command` with `{"action":"invalid_action"}` throws inside the inner tool, catches it, and returns `{"Success":false,...}` at `Assets/CoreAiUnity/Runtime/Source/Features/World/WorldLlmTool.cs:353-358`, `Assets/CoreAiUnity/Runtime/Source/Features/World/WorldLlmTool.cs:435-442`, and `Assets/CoreAiUnity/Runtime/Source/Features/World/WorldLlmTool.cs:888-895`. Neither path throws out to MCP. The MCP envelope consequently advertises a successful tool call; clients relying on `isError` misclassify failed commands and skip tool-error handling.
- Existing guards/tests: required `action` is checked in the world wrapper, but a nonempty unknown action passes it. Other wrappers already map inner failure (`Assets/CoreAIMcp/Runtime/Tools/ManageModsMcpTool.cs:80-91`, `Assets/CoreAIMcp/Runtime/Tools/ExecuteLuaMcpTool.cs:102-104`). The inner failure contracts are asserted by `Assets/CoreAIMods/Tests/EditMode/LuaLogServiceEditModeTests.cs:340-348` and `Assets/CoreAiUnity/Tests/EditMode/WorldToolEditModeTests.cs:111-136`. MCP tests do not exercise either wrapper's failure envelope.
- Fix direction: convert the inner result's actual success field to `McpToolResult.IsError`, accounting for the world result's uppercase `Success` and logs' lowercase `success`. Preserve the original content and distinguish cancellation from ordinary failure.
- Regression: call both wrappers through the dispatcher, directly and through the broker. Assert `result.isError == true` for unknown log level, unknown/missing-parameter world action, and an executor refusal; assert false for success. For parameter rejection, assert the backing executor/query was not invoked.

### MCP-003 — P2 — Static stop/start leaks persistent hosts and loses running-call accounting

- Status: new; no corresponding open TODO entry found. Confidence: high from deterministic object/reference lifetime; no Unity allocation measurement performed.
- Evidence: `Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:602-619` reuses only `_active`; when it is null, it creates a new GameObject and calls `DontDestroyOnLoad`. `StopServer` calls `StopListening` (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:623-625`), which clears `_active` without destroying or retaining the automatically created host (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:362-372`). The stopped host stays enabled and retains its component/queue state; there is no owned-host cleanup path.
- Trigger/impact: with a built composition present, repeatedly use the documented `StartServer` / `StopServer` API. Each successful cycle leaves a `CoreAI_McpServer` in the persistent scene and the next start creates another. Live-session memory and idle `Update` calls grow with every cycle. More seriously, a body still running after cancellation retains `_runningCalls` only on the abandoned component (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:87-95`, `Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:273-282`); the next static start has a fresh capacity of 64. Repeated restarts can accumulate such bodies outside the intended restart admission accounting.
- Existing guards/tests: a same-component restart correctly preserves running leases. `Assets/CoreAIMcp/Tests/PlayMode/CoreAiMcpServerResidencyPlayModeTests.cs:258-284` tests that route by calling `_server.StartListening` again. No package test calls `StartServer` or `StopServer`; it cannot catch the static API's different lifetime.
- Fix direction: retain and reuse a separately owned automatic host across stop/start, with explicit eventual disposal that respects outstanding bodies. Do not lose the component that owns running leases. Keep scene-owned host destruction separate from owned-host cleanup.
- Regression: a deterministic no-model PlayMode test should run repeated static start/stop cycles against a test composition, yield destruction frames if needed, and assert persistent host count stays bounded. Hold a cancellation-ignoring fake body across a static restart and assert the new admission count still includes it; release it and assert capacity returns exactly once.

### MCP-004 — P3 — Windows access-error guidance reserves a different URL from the listener

- Status: new; no corresponding open TODO entry found. Confidence: high for the mismatched strings; Windows ACL behavior was not exercised.
- Evidence: the actual registration is `http://127.0.0.1:<port>/` at `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:124-130`; the startup catch prints `netsh http add urlacl url=http://127.0.0.1:<port>/mcp/ ...` at `Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:352-357`. The source explicitly explains that `/mcp/` was replaced with the root prefix so `/mcp` without a trailing slash can work.
- Trigger/impact: on a Windows host where startup needs a URL reservation, follow the printed fix. It reserves a child path rather than the root prefix the process registers, so the diagnostic does not authorize the requested listener prefix and setup remains blocked. This is a diagnostic/configuration defect, not evidence that all Windows starts fail.
- Existing guards/tests: bind errors are caught and dispose the failed transport, but none of the reviewed tests asserts that the suggested reservation matches the real prefix. Socket fixtures skip on URL ACL refusal instead.
- Fix direction: derive the diagnostic reservation from the same canonical listener prefix; document the endpoint URL separately.
- Regression: exercise an injected/fake bind-denied path and assert the suggested ACL URL exactly equals the registered prefix, including the trailing slash. A pure formatting/adapter test is sufficient; it must not run `netsh` or require administrator rights.

## Observed safeguards and configurable seams

These are source observations, not executed pass claims.

- Admission: the component is off by default and requires a bearer token by default (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:45-60`). It resolves a configured token, then environment, then crypto-random bytes (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:375-393`; `Assets/CoreAIMcp/Runtime/Server/McpRequestGuard.cs:29-40`). Token logging and deliberately disabled auth are documented operator choices; no new auth-bypass finding is established.
- Transport trust boundary: `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:129` binds loopback. Every HTTP method enters local-address, Host, Origin, auth, session and version checks before routing (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:263`, `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:351-402`). Session ids are correlations, not bearer replacements. The public lower-level transport's default null token explicitly disables auth; hosts using it must choose auth themselves.
- Resource limits: 64 transport slots and nonblocking overload rejection (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:55`, `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:233-252`); a 4 MiB default byte cap including chunked bodies (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:31-32`, `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:457-470`); 10-second body and 5-second write deadlines with bounded rejection drain (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:41-45`, `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:426-449`). Sessions default to 64 and one hour, guarded by a lock and injectable clock (`Assets/CoreAIMcp/Runtime/Server/McpSessionStore.cs:19-39`, `Assets/CoreAIMcp/Runtime/Server/McpSessionStore.cs:46-100`). These are finite bounds; they do not establish acceptable device heap or throughput.
- Notification ordering/backpressure: subscriptions are capped independently, one current stream per session; reconnect cancels the old stream (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:528-544`). A size-one signal coalesces catalog revisions, idle writes are keepalives, and cleanup removes only its own current binding (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:556-607`). Old HTTP handlers can briefly coexist with replacements, still subject to the 64 request slots.
- Dispatch/order/idempotency: JSON-RPC envelope and object-argument validation precede tool capture (`Assets/CoreAIMcp/Runtime/Server/McpRpcDispatcher.cs:74-99`, `Assets/CoreAIMcp/Runtime/Server/McpRpcDispatcher.cs:151-169`). Captured arguments and exact bindings survive a queue delay; admission revalidates direct and broker targets atomically, then invocation is one-shot (`Assets/CoreAIMcp/Runtime/Tools/McpToolRegistry.cs:93-145`). This prevents a queued request from being redirected by catalog replacement. JSON-RPC ids are echoed, not a cross-request deduplication key; no exactly-once network retry guarantee is established.
- Main-thread lifecycle: the host counts queued plus actually running bodies, pumps one queue snapshot within a between-call frame budget, removes timed-out queued work, and does not release a running lease until its body completes (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:214-286`, `Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:414-450`). HTTP stop cancels the transport token and aborts tracked responses, with an asynchronous completion task (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:144-188`). Synchronous tools can overrun a frame; the budget cannot preempt them, as documented. Static restart is the separate MCP-003 defect.
- Authority: `manage_mods` requires explicit admission, nonblank matching actor id, and a trusted unrestricted composed identity (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:482-537`). The provider passes it into the actor-aware wrappers (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpToolProvider.cs:52-69`); `LuaModsLlmTool` calls actor-aware runtime operations. No remote-supplied actor/envelope fields are accepted by MCP. Existing TODO history records the server-generated envelope fix at `TODO.md:1915-1918`; it is not reported as new.
- Composition/platform: `IMcpTool`, residency policy, screenshot source, main-thread dispatcher, explicit live registry and provider inputs allow alternate composition without a scene scan. The default component still builds concrete adapters; custom composition can omit/replace them. Package/asmdef review found no Editor-only runtime reference in MCP, and the README records its one-assembly thin-adapter deviation. The component returns before listener startup on WebGL (`Assets/CoreAIMcp/Runtime/Server/CoreAiMcpServer.cs:300-307`). MCP itself does not write files; persistence is delegated to the Mods/world services and is outside this report's ownership.

## Hypothesis requiring validation

### MCP-H001 — Overload-response failure may terminate the accept loop

At `Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:233-238`, the capacity-rejection `StatusCode`/`Close` path is outside the accept-operation try/catch and outside `HandleContextAsync`'s error isolation. If an HttpListener response operation throws for a reset/disposed client here, `AcceptLoopAsync` faults while the listener may remain listening and `IsRunning` may remain true. Whether the relevant response-close failure is observable on the target Unity/OS implementation was not established; this is not counted as a confirmed bug. Root should use an adapter/fault-injection test or an authorized loopback fault test with all 64 slots occupied, reset overload clients, and then verify healthy requests still receive a response and completion reports any failure.

## Missing validation and explicit limitations

- Wire cancellation: all valid notifications, including a potential `notifications/cancelled`, are currently accepted as no-ops (`Assets/CoreAIMcp/Runtime/Server/McpRpcDispatcher.cs:95-99`). Tools receive the server lifetime token, not a per-request CTS (`Assets/CoreAIMcp/Runtime/Server/McpHttpServer.cs:305-307`). Existing cancellation tests inject a CTS directly or stop the server; they do not prove a real client's cancel notification cancels a tool. Once a body starts, the queue timeout intentionally stops applying. Thus a cooperative long-running custom tool has no explicit client-cancel route short of server stop. This source-verified limitation is separated from bugs because the package documents a minimal notification/method subset; root should decide the client-cancellation contract and add a wire-level test before claiming support. Do not equate an SSE reconnect/disconnect with an explicit cancellation request.
- Existing open validation debt: `TODO.md:2538-2539` names `GetModLogsMcpTool`, `ManageModsMcpTool`, `WorldCommandMcpTool`, and `MainCameraScreenshotSource`. MCP-002 gives two concrete consequences; the rest remains missing validation, not presumed defects.
- Rendering: screenshot tests use a fake capture source; the residency PlayMode test accepts a screenshot failure message. They do not prove a real camera renders a valid PNG, preserves target/render state after failure, or works under the installed URP 17.6 path (`Packages/manifest.json:21`). `Assets/CoreAIMcp/Runtime/Server/MainCameraScreenshotSource.cs:44-86` still needs graphics/device validation, including render-pipeline behavior. No rendering incompatibility is claimed from grep alone.
- WebGL: `Assets/CoreAIMcp/Tests/EditMode/CoreAiMcpServerWebGlEditModeTests.cs:14-18` only asserts that the Editor is not a WebGL player; it does not execute the browser early-return branch or prove no socket/task startup occurs there. No WebGL persistence write is owned by MCP.
- Pressure/fault/shutdown: no executed evidence here for request-slot exhaustion/recovery, repeated transport start failure, slow writes under sustained backpressure, late admission racing stop, or restart before old handler completion. Default body slots alone allow 64 times 4 MiB = 256 MiB of simultaneous raw request data before strings/DOM/result allocations; acceptable total heap and frame impact require a host budget and measurement. This arithmetic is not a memory measurement or a demonstrated out-of-memory defect.
- Package-consumer validation: MCP architecture/version fixtures locate sources through `Application.dataPath/CoreAIMcp` (`Assets/CoreAIMcp/Tests/EditMode/McpArchitectureFitnessEditModeTests.cs:38`, `Assets/CoreAIMcp/Tests/EditMode/McpPackageVersionEditModeTests.cs:19`).
