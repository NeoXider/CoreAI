## Confirmed actionable findings

### NET-001 — P2 — A throwing request completion skips world disconnection

**Status:** new; no matching open TODO found. **Confidence:** high from the complete source call chain; not executed.

**Trigger:** an admitted connection has an outstanding server-to-client request whose `Action<RbxNetworkResponse>` throws when the peer disconnects. The callback is a public composition seam, not constrained to a nonthrowing implementation.

**Evidence and guards:** `Assets/CoreAIMirror/Runtime/CoreAiMirrorNetworkBridgeProvider.cs:677` calls `NotifyDisconnected`. In `Assets/CoreAIMirror/Runtime/MirrorNetworkBridge.cs:940`, `FailPendingFor` runs before `PeerDisconnected` at line 941. `FailPendingFor` invokes callbacks without containment at line 2692. A throwing callback therefore skips `PeerDisconnected`, but the `finally` still reaches `ReleaseConnection` at line 953. `ReleaseBinding` emits `BindingReleased` at line 2660; `CoreAiMirrorSessionHost.OnBindingReleased` (`Assets/CoreAIMirror/Runtime/CoreAiMirrorSessionHost.cs:255`) removes the session and identity without calling the world. The world teardown is exclusively on the skipped `OnPeerDisconnected` path (lines 226-236, then `Release` at line 298). The provider catches the exception at line 680, so logging it does not restore teardown.

**Impact:** the transport/session maps can report a clean departure while the world's Player, actor-owned mods, signal connections and chat resources remain. The cleanup in `Assets/CoreAIMods/Runtime/Scripting/LuaCs/LuaCsRbxApiBindings.cs:1564` through line 1598 is never called. Further cleanup cannot locate the removed session. This is a failure-isolation defect, not a claim of a remote privilege escalation.

**Existing tests:** `Assets/CoreAIMirror/Tests/EditMode/MirrorBridgeRulesEditModeTests.cs:200`, `:247` cover ordinary and reentrant completions; `Assets/CoreAIMirror/Tests/EditMode/MirrorRestartEditModeTests.cs:267` covers a throwing world teardown. None supplies a throwing pending completion before the session host hears the disconnect. `Dispose` already uses callback containment (`MirrorNetworkBridge.cs:1448`, `:2717`), showing that this failure class is anticipated elsewhere.

**Fix direction:** make completion failure unable to suppress mandatory peer/world teardown; isolate each completion and each essential lifecycle subscriber, preserve exactly-once removal, and continue failing the remaining requests. Avoid merely catching at the provider boundary, where cleanup has already been bypassed.

**Regression recommendation:** admit a real world actor through the session host, start two `InvokeClient` requests, make the first completion throw, then drop the connection through `OfflineMirror`. Assert one world disconnect/PlayerRemoving, no Player or actor-owned resources, zero sessions/identities/bindings, both callbacks attempted once, no later timeout completion, and no exception escaping the transport tick.

## Known limits and hypotheses not promoted

- Existing product gaps remain open: receive-side rate limiting, Mirror host-mode local-client remotes, refusal-response delivery, restart state/order, transport/player capacity, runtime world-session handover, protocol negotiation and world-state replication. References: `TODO.md:1071-1092,1596-1618,1631-1675`; `Assets/CoreAIMirror/README.md:19-23,244-277`. These are not new NET counts and are not silently accepted as working features.
- A 30-second timeout is enforced when the frame pump visits an entry. `CompleteResponse` checks an open id, not its deadline; the late-response test first pumps the expiry (`MirrorBridgeRulesEditModeTests.cs:153-174`). Exact receive-versus-pump ordering at the deadline needs an explicit policy and focused test before treating it as a separate defect. The source proves no double completion after removal, not a hard real-time deadline.
- `uint` correlations advance without a collision/wrap guard (`MirrorNetworkBridge.cs:326,1257-1258`). No reachable ordinary workload or retained-open-entry trigger across the full wrap was established; this remains a hypothesis, with no severity/count added.
- Per-connection holds, timeouts and handler budgets do not prove bounded total memory or roughly 100-player support. Packet decoding, authentication input size, aggregate pending work and a host that stops pumping need a separate fault/capacity contract. This pass neither measured those resources nor reviewed the third-party Mirror transport internals.
