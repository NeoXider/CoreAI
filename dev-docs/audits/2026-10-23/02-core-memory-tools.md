## Confirmed findings

### MEM-001 — P1 — Empty actor scope defeats enqueue-time user isolation

**New finding; high confidence from the complete source path.** With the default local actor and a host-provided mutable `IAgentMemoryScopeProvider`, enqueue a request for learner A while another request occupies the queue, then switch the provider to learner B before execution. The queued request reads and writes B's memory/history instead of A's. A provider change during a suspended turn can also split that turn between partitions.

- `Assets/CoreAI/Runtime/Core/Features/Orchestration/QueuedAiOrchestrator.cs:146` resolves a trusted actor before creating the work item. At `:157`, any actor context wins over `CaptureMemoryScope`, including an actor whose memory scope is empty.
- Execution pushes that actor context at `Assets/CoreAI/Runtime/Core/Features/Orchestration/QueuedAiOrchestrator.cs:426`.
- `Assets/CoreAI/Runtime/Core/Features/AgentMemory/AgentMemoryScope.cs:70` resolves an empty-scope local actor against the provider on each store call; `:79` does the same for named actors with no own scope. It does not capture the provider scope at admission.
- Production composition registers the real `AiOrchestrator` and wraps it with `QueuedAiOrchestrator` (`Assets/CoreAiUnity/Runtime/Source/Composition/CorePortableInstaller.cs:112`). The inner resolves an actor for every request (`Assets/CoreAI/Runtime/Core/Features/Orchestration/AiOrchestrator.cs:104`), so the queue's otherwise-correct actorless capture branch is bypassed. The composition-issued local actor explicitly has an empty scope (`Assets/CoreAI/Runtime/Core/Authority/IActorIdentityProvider.cs:147`).
- The existing regression `ScopeSnapshot_PendingTaskRunsAndPersistsUnderEnqueueTimeStudent` uses `ScopedPersistenceOrchestrator` (`Assets/CoreAiUnity/Tests/EditMode/QueuedAiOrchestratorEditModeTests.cs:574`), which does not implement the actor resolver; its queue construction at `:1380` therefore exercises the other branch. Actor-scope tests cover fixed providers, not a provider switch within one captured actor (`Assets/CoreAiUnity/Tests/EditMode/AgentMemoryActorScopeKeyEditModeTests.cs:165`).

**Fix direction:** capture the effective actor-plus-host memory scope once at admission and use that immutable binding for memory, history, transcript, and summary throughout execution and rejected/cancelled-turn persistence. Preserve trusted actor issuance and empty-scope legacy behavior. **Regression:** repeat the pending-task, pending-stream, and pending-cancellation tests with the real actor-resolving inner and the default local actor; pause a model/tool await, switch learners, and assert all stores retain A's key. Owning report: MEM; report 01 should cross-reference this queue-boundary issue rather than duplicate it. No runtime reproduction was run.

### MEM-003 — P2 — Memory and inventory tools convert cancellation into ordinary failures

**New finding; high confidence.** Cancel a pending `IAtomicAgentMemoryStore.MutateAsync` or inventory provider read. The first-party tool returns failure JSON and may log an error instead of propagating cancellation. A pre-cancelled `memory read` still loads and discloses the document. This undermines callers' cancellation contract and can let the tool policy treat a cancelled invocation as normal feedback.

- `Assets/CoreAI/Runtime/Core/Features/AgentMemory/MemoryTool.cs:84` dispatches reads with no token check; `:150` catches every exception from mutation, including `OperationCanceledException`, and returns failure JSON at `:157`.
- `Assets/CoreAI/Runtime/Core/Features/AgentMemory/InventoryTool.cs:46` passes the token to the provider, but `:59` catches its cancellation and converts it to a failed result.
- The policy deliberately rethrows caller cancellation only when an exception reaches its boundary (`Assets/CoreAI/Runtime/Core/Features/Llm/ToolExecutionPolicy.cs:997`); returned tool JSON goes through ordinary success/failure processing at `:903`.
- `Assets/CoreAiUnity/Tests/EditMode/AgentMemoryConcurrencyEditModeTests.cs:86` checks concurrent appends with no cancelled token. The file-store memory-tool tests cover write/read failures and successful durability (`Assets/CoreAiUnity/Tests/EditMode/FileAgentMemoryStoreEditModeTests.cs:441`, `:457`, `:470`), not cancellation.

**Fix direction:** check cancellation before read/dispatch and rethrow `OperationCanceledException` separately. Preserve an explicit committed outcome if cancellation arrives after a storage effect, rather than falsely reporting an uncommitted failure. **Regression:** fake stores/providers that block and then throw cancellation; assert cancellation escapes both direct invocation and policy invocation, no failure log is emitted, and pre-cancelled reads never reach storage. Add a controlled after-write cancellation case to establish honest effect receipts. No runtime test run.

- The stranded semaphore is static and reused across instances for the same path (`Assets/CoreAiUnity/Runtime/Source/Features/AgentMemory/Infrastructure/FileAgentMemoryStore.cs:127`, `:1624`); disposing the old store cannot reset it. The existing lock-release tests use a live store throughout (`Assets/CoreAiUnity/Tests/EditMode/FileAgentMemoryStoreEditModeTests.cs:67`). Summary-store disposal is separately tested (`Assets/CoreAiUnity/Tests/EditMode/FileConversationSummaryStoreEditModeTests.cs:545`), but that protection is not present in the memory store.

**Fix direction:** protect the outer gate immediately after acquisition, including failures acquiring the inner one; use an admission/lifetime state that rejects new work and lets admitted operations settle before disposing owned semaphores. Do not dispose shared gates while peers/waiters can hold them. **Regression:** dispose an old instance, attempt both history reads, then assert a new peer can mutate/read the same role within a bounded deadline; also control disposal between the two acquisitions. The in-memory probe checked the exact acquisition/`try` order with .NET semaphores; no repository class or filesystem was executed.
