# Server bridge extraction assessment

Status: complete source assessment, updated 2026-10-26 for the user's explicit requirement that ordinary non-Unity applications can use the feature. No implementation or executed runtime proof is supplied by this report. Only this file was written by this worker.

## Recommendation

Implement **CoreAI Gateway Client** as an optional portable feature inside the existing **com.neoxider.coreai / CoreAI.Core** package, with thin Unity transport and composition adapters in **com.neoxider.coreaiunity / CoreAI.Source**. Portable runtime functionality must compile for netstandard2.1 with BCL Task/CancellationToken/IAsyncEnumerable and existing MEAI/HTTP contracts, without UnityEngine, UniTask, VContainer or MessagePipe. Reuse `LlmExecutionMode.ServerManagedApi`, `OpenAiHttpOptions`/`IOpenAiHttpSettings`, `MeaiOpenAiChatClient`, `IOpenAiHttpTransport` and `HttpClientOpenAiTransport`. Unity continues to select its existing UnityWebRequest/fetch-SSE transports. Do not add a completion parser or execution mode.

`CoreAiPro` is a client adapter, not a server implementation. Its gateway class performs entitlement/usage side calls; it never sends LLM completions. `CoreAIServer` would misrepresent it. Do not add an eighth UPM package: the reusable contracts, options, MEAI and HttpClient dependencies already live in CoreAI.Core. A separate package is justified only by a concrete dependency/distribution/release boundary; none is required here. The proposed portable path is `Assets/CoreAI/Runtime/Core/Features/Llm/Gateway/`; Unity adapters are proposed under `Assets/CoreAiUnity/Runtime/Source/Features/Llm/Infrastructure/Gateway/`. Neither is an existing implemented GatewayClient inventory: tracked-file search found no LLM GatewayClient module.

The critical prerequisites are **portable real policy/usage consumers and scoped authorization**. A portable MEAI.IChatClient wrapper must call optional entitlement/usage around actual model sends; DI registration alone is insufficient. Auth/refresher/header bindings belong to one client/scope/endpoint. Preserve Source static APIs as compatibility fallback. Do not make them a prerequisite of .NET or new Unity composition. The human owner requested copying their own Neoxider package into CoreAI and publication is authorized; preserve provenance/copied notices without inventing a new permission gate.

Entitlement and usage endpoints are optional gateway protocol features. Their defaults should be disabled so that an ordinary OpenAI-compatible relay works without implementing RedoSchool-like `/entitlement` or `/usage` routes. The server remains authoritative for authorization, quotas, rate limits, billing, and model choice.

## Goal, requirements, and scope decisions

Before planning, the real goal is reusable requests through a developer-selected server from CLI/desktop/service/Unity hosts, with replaceable identity and optional gateway services. Required properties are cancellation propagation, buffered/streaming wire behavior, no provider secrets in shipped clients, typed statuses, scoped identities, bounded telemetry, explicit disposal and operation in built players including WebGL. Single-player, player-host co-op, dedicated-server and embedded hosts must remain possible. A server-managed LLM route does not select the game's networking topology.

Conventions are runtime-first/replaceable blocks, English prose/logs, existing interfaces, declarative Unity installers and injected portable ILog. Portable methods use Task-based contracts; the gameplay UniTask convention is not a reason to put UniTask into CoreAI.Core. No game login, student/account/session store, billing rules, backend deployment/implementation, scene, prefab, settings asset or secret configuration belongs in this extraction. Do not move the full host MeaiLlmClient or expand portable execute-as-you-stream tooling as a side effect of this rename.

## Runtime composition and compatibility

1. Plain .NET composition is DI-free: OpenAiHttpOptions(ExecutionMode=ServerManagedApi, ApiKey empty, endpoint configured, Model optionally empty) + injected per-client auth/header binding + existing HttpClientOpenAiTransport -> MeaiOpenAiChatClient -> GatewayChatClient. Compose existing SmartToolCallingChatClient outside the gateway leaf for buffered tool execution. No CoreAILifetimeScope/GameObject/Unity logger/global startup is needed.
2. GatewayChatClient checks the optional policy before a leaf send and records its usage afterward, for buffered and streaming paths including failure/cancellation/disposal. Define the accounting unit as one model request/roundtrip; an outer tool turn can have several. Do not also forward Source aggregate events as the same record. Servers remain authoritative.
3. Freeze the public metadata API before implementation: an injected request/context factory or explicit bound role/route supplies LlmCompletionRequest with actual materialized ChatHistory, role, trace and resolved LlmRouteProfile. Enumerate the caller's messages once; reuse LlmRequestContext when present and restore nested scopes. No identity inferred from a prompt.
4. Auth/refresher/headers belong to one client/scope/endpoint. Dynamic bearer rotates per send and before one auth retry; custom/correlation/idempotency headers remain a snapshot during retry. Later invocation with reused request takes a new snapshot. Reserved transport headers cannot be injected via custom headers. Scoped construction must override/avoid both legacy global auth registries, including metadata header injection.
5. Auth refresh stays around the raw model request, inside the outer tool loop, so it cannot replay an entire tool turn. Retry once only on admissible auth failure before observable text/native function-call/tool content; failed/missing refresher returns typed error. Host refresher contract owns concurrent single-flight/cancelled-waiter behavior. New scoped Unity path must not also use a second Source refresh wrapper.
6. Enabled policy must actually run. Deny -> typed terminal failure and zero completion sends for both modes. Cancellation before/during preflight propagates and prevents dispatch. Disabled policy -> zero entitlement calls. Unavailable/invalid response follows an explicit configured availability policy, never masquerades as a verified allow or overrides a valid deny. No keyed provider fallback on denial.
7. Keep optional telemetry disabled by default and simple when enabled: directly await best-effort reporting under a configurable finite deadline/concurrency bound, observe failures, and preserve successful primary result. Document bounded added latency. No unobserved Task, unbounded queue or new background/durable scheduler. If queued delivery is chosen, capacity/drop/shutdown become explicit tested contracts. Do not retry usage POST without server-supported deduplication.
8. Existing ServerManagedApi enum/profiles/settings fields/constructors/static hooks remain compatible. New feature can be configured/replaced/omitted through portable factory inputs and Unity installer without package code edits. No auth stub/login requirement, game topology change, Mirror/Hub/Mods dependency or local/offline/direct-provider regression. COREAI_LLM gating remains; verify on/off compilation.

## Protocol, platform, and failure behavior to preserve

- **Completions:** existing POST `<base>/chat/completions`, buffered JSON and SSE; under ServerManagedApi an unset client model is omitted so the backend chooses it. Preserve server-returned model metadata. Do not invent `/relay` or require a new proxy protocol.
- **Vision/tools:** existing OpenAI `image_url` parts and native tool definitions/results stay in the reused pipeline. Preserve tool ordering and executed-call receipts; no replay after a tool ran or visible streaming text committed. Actual gateway/provider support was not checked.
- **Status:** current completion mapping includes 401/403 to AuthExpired, 409/quota-body to QuotaExceeded, 402 to PaymentRequired when not already classified as quota, and 429 to RateLimited. Preserve Retry-After and typed failures. A 403 is not separately treated as authorization denial by this existing client; do not silently promise different semantics.
- **Cancellation/disposal:** cancellation must reach HTTP, preflight, stream enumeration and usage lifetimes. Early iterator disposal must release transport/registry leases. Refresh happens at most once per logical invocation and must not reissue committed side effects. Concurrent refresh safety is a host refresher contract; the extracted bearer adapter does not mint or refresh tokens itself.
- **Resource bounds:** completion WebGL fetch already has configurable backlog byte/chunk bounds. Preserve its existing backpressure behavior. Add explicit pending/concurrent limits only for the new telemetry/side-call path; cap side-call response bodies/error excerpts. Do not claim the original DownloadHandlerBuffer is bounded: it is not bounded by this source. Long provider streams and malformed/truncated SSE still need integration tests rather than a second parser.
- **WebGL:** retain existing fetch SSE plus UnityWebRequest composite for streaming and buffered requests. Without native streaming enabled, UnityWebRequest advertises no SSE and the existing client simulates updates after a buffered completion. Do not label that token-by-token network streaming. No ThreadPool, Task.Run, blocking wait, or ConfigureAwait(false) on the new Unity path. CORS must permit the chosen bearer/custom headers and methods; browser/server behavior remains unverified.
- **Startup/logout:** install declaratively per scope; no automatic network warmup, student login, static owner replacement or Editor-only prerequisite. Dispose subscriptions, cancel owned work and drop credentials on scope teardown/logout. Repeated play sessions with domain reload disabled must not retain the new feature's identity/subscriptions. Existing static hook files have no local SubsystemRegistration reset; a new scoped adapter cannot rely on an unverified global reset elsewhere.
- **Trust:** raw bearer tokens are provided by the host and never logged/persisted into sample assets. Provider keys and project provisioning secrets stay outside public clients. Client tenant/user/role/lesson/correlation headers are untrusted metadata; the server must derive/validate authority from its own credential policy. The assessment did not verify that server behavior.
