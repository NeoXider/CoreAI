# Command (Tool Call) Format Under MEAI

This document describes the **internal** command (tool call) format generated by models when using functions. With native MEAI (Microsoft.Extensions.AI) function calling, this format is managed automatically.

---

## General Tool Call Format (Internal Structure)

When the model decides to invoke a tool, a structure equivalent to the following MEAI format is produced:

```json
{
  "name": "tool_name",
  "arguments": {
    "param1": "value1",
    "param2": "value2"
  }
}
```

> [!WARNING]
> **DO NOT SPECIFY THIS FORMAT IN PROMPTS.**  
> The native MEAI client automatically passes the tool schema (JSON Schema) to the model. If you manually ask the model to return JSON text, it will respond with ordinary text containing JSON instead of triggering a system (native) tool invocation. In prompts, simply say: "Use the tool [name]."

## 1. Memory Tool (all roles with memory)

**Roles:** every built-in role except PlainChat; custom agents with `.WithMemory()`

### Write (overwrite)
```json
{
  "name": "memory",
  "arguments": {
    "action": "write",
    "content": "Wave 7: difficulty increased, EliteBoss spawned at (50,0,50)"
  }
}
```

### Append
```json
{
  "name": "memory",
  "arguments": {
    "action": "append",
    "content": "Craft#3: Steel + Ice Crystal → Frostblade damage:55 ice:20"
  }
}
```

### Clear
```json
{
  "name": "memory",
  "arguments": {
    "action": "clear"
  }
}
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|:--------:|-------------|
| `action` | string | Yes | `read` / `write` / `append` / `clear` / `str_replace` / `insert` / `delete` / `rename` |
| `content` | string | For `write` / `append` (and `insert`) | Text to store |
| `old_text` / `new_text` / `anchor` / `line` / `replace_all` | various | For the granular edits | See [MemorySystem.md](MemorySystem.md) |

**Result:** a JSON `MemoryResult` (`Success`, `Message` such as `"DONE: Memory saved for Creator."`, `Error`,
`Version`, `MemoryLength`, and `Memory` with the document text for `read`).

## 2. Execute Lua Tool (Programmer)

**Roles:** Programmer (attached automatically by the Mods package); custom agents with `LuaLlmTool`

> [!NOTE]
> `execute_lua` ships in the optional `com.neoxider.coreaimods` package (requires `COREAI_LUA`).
> Runtime Lua execution runs on **Lua-CSharp** (`LuaCsSecureEnvironment`), a managed, AOT-safe VM
> that works on IL2CPP and WebGL players.

### Execute Lua code
```json
{
  "name": "execute_lua",
  "arguments": {
    "code": "local dmg = 45 + math.random(10)\nreport('damage: ' .. dmg)"
  }
}
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|:--------:|-------------|
| `code` | string | Yes | Lua code to run in the sandbox |

**Available Lua API** (default Programmer composition):

| Function | Description |
|----------|-------------|
| `report(string)` | Send result back |
| `add(a, b)` | Add two numbers |
| `coreai_world_find(pattern)` / `coreai_world_pos(name)` / `coreai_world_exists(name)` | Read-only scene queries |
| `coreai_world_list_prefabs()` / `coreai_world_raycast(...)` | Read-only prefab list and raycast |
| Rbx API: `Instance.new('Part')`, `game`, `workspace`, `Vector3`, `CFrame`, `Color3`, … | Create and edit world objects; see [RBX_API.md](../../CoreAI/Docs/RBX_API.md) |

The build functions below publish world and component commands. The default `RegisterCoreAiMods`
composition withholds them (`LuaCsModStackOptions.RegisterWorldEditBuildBindings = false`): a call raises an
error that points to the Rbx API. A Lua stack you build yourself with `LuaCsModRuntimeFactory` keeps them
(the option defaults to `true`).

| Function | Description |
|----------|-------------|
| `coreai_world_spawn({prefab=..., name=..., x?, y?, z?, rx?, ry?, rz?, scale?, scaleX?, scaleY?, scaleZ?, parent?})` | Spawn object; `prefab` and `name` required, transform and parent optional |
| `coreai_world_change(name, {x?, y?, z?, rx?, ry?, rz?, scale?, scaleX?, scaleY?, scaleZ?, parent?})` | Apply only supplied transform or parent fields |
| `coreai_world_set_color(name, htmlColor)` | Set renderer colour |
| `coreai_world_destroy(name)` | Destroy an object |
| `coreai_world_set_active(name, active)` | Enable/disable an object |
| `coreai_world_spawn_batch({...})` / `coreai_world_grid(...)` | Spawn several objects in one call |
| `coreai_world_begin()` / `coreai_world_commit()` / `coreai_world_rollback()` | Group world edits into a transaction |
| `coreai_world_load_scene(sceneName)` | Load a scene |
| `coreai_world_reload_scene()` | Reload the scene |
| `coreai_world_play_animation(name, anim)` | Play an animation |
| `coreai_world_play_sound(...)` | Play a sound |
| `coreai_component_add(name, type)` | Add a supported component |
| `coreai_component_remove(name, type)` | Remove a supported component |
| `coreai_component_set_number(name, type, property, value)` | Set numeric component property |
| `coreai_component_set_bool(name, type, property, value)` | Set boolean component property |
| `coreai_component_set_text(name, type, property, value)` | Set text, colour, or enum component property |
| `coreai_component_set_vector(name, type, property, x, y, z)` | Set vector component property |

**Result:** JSON `{"Success":true,"Output":"…"}` on success (`Output` omitted when the chunk returned nothing), or
`{"Success":false,"Error":"…"}` — for example `Lua code is required` for whitespace-only code, a sandbox limit
(`sandbox: EXCEEDED_HARD_LIMIT_STEPS (…)`, `sandbox: Lua exceeded … ms.`, `sandbox: EXCEEDED_MEMORY_BUDGET (… bytes)`),
or the Lua error text. The model
reads the error and may retry in the same turn.

### Multi-line Lua example

```json
{
  "name": "execute_lua",
  "arguments": {
    "code": "-- Ambush markers\nfor i = 1, 2 do\n  local p = Instance.new('Part')\n  p.Name = 'ambush_' .. i\n  p.Anchored = true\n  p.Position = Vector3.new(i * 20 - 30, 1, 5)\n  p.Parent = workspace\nend\nreport('Ambush setup: 2 markers')"
  }
}
```

## 3. World Command Tool (Creator / Builder)

**Roles:** Creator and Builder (attached automatically); custom agents with `WorldLlmTool`

### Spawn - create object
```json
{
  "name": "world_command",
  "arguments": {
    "action": "spawn",
    "prefabKey": "Enemy",
    "targetName": "enemy_wave7_1",
    "x": 10,
    "y": 0,
    "z": 5,
    "fy": 90,
    "scaleX": 2,
    "scaleY": 1,
    "scaleZ": 3,
    "stringValue": "WaveRoot"
  }
}
```

`prefabKey` and `targetName` are required. Position, rotation (`fx/fy/fz`), uniform `scale`, per-axis
`scaleX/scaleY/scaleZ`, parent (`stringValue`), and `worldPositionStays` are optional. When a parent is set,
coordinates are local by default (`worldPositionStays: false`); `true` preserves world space. Without a
parent, local and world coordinates are identical. `scale` is a uniform fallback; use per-axis scale for
meter-accurate dimensions.

For compound objects, create a named `empty` root first and parent related pieces beneath it instead of
leaving every piece at scene root.

`prefabKey` may be a registered prefab key or a built-in primitive key (`cube`, `sphere`, `cylinder`, `capsule`, `plane`, `empty`) when `AllowWorldPrimitives` is enabled. Registered prefabs take precedence.

### Change - partial transform/hierarchy edit
```json
{
  "name": "world_command",
  "arguments": {
    "action": "change",
    "targetName": "enemy_wave7_1",
    "x": 12,
    "fy": 180,
    "scaleY": 1.5,
    "stringValue": "none"
  }
}
```

`change` applies only supplied fields. Omitted axes and fields stay unchanged. Use `stringValue: "none"` to detach from the current parent.

### Set color
```json
{
  "name": "world_command",
  "arguments": {
    "action": "set_color",
    "targetName": "enemy_wave7_1",
    "stringValue": "#ff3300"
  }
}
```

### Destroy - remove object
```json
{
  "name": "world_command",
  "arguments": {
    "action": "destroy",
    "targetName": "OldBuilding"
  }
}
```

### List Objects - object list
```json
{
  "name": "world_command",
  "arguments": {
    "action": "list_objects"
  }
}
```

### List Objects - name filter
```json
{
  "name": "world_command",
  "arguments": {
    "action": "list_objects",
    "stringValue": "enemy"
  }
}
```

### Load / reload scene
```json
{
  "name": "world_command",
  "arguments": {
    "action": "load_scene",
    "stringValue": "Level_2"
  }
}
```

```json
{
  "name": "world_command",
  "arguments": {
    "action": "reload_scene"
  }
}
```

### Other runtime actions
```json
{"name":"world_command","arguments":{"action":"set_active","targetName":"SecretDoor"}}
{"name":"world_command","arguments":{"action":"play_animation","targetName":"Boss1","animationName":"rage_attack"}}
{"name":"world_command","arguments":{"action":"stop_animation","targetName":"Boss1"}}
{"name":"world_command","arguments":{"action":"list_animations","targetName":"Boss1"}}
{"name":"world_command","arguments":{"action":"play_sound","targetName":"Alarm","stringValue":"alarm_clip","volume":0.8}}
{"name":"world_command","arguments":{"action":"set_volume","targetName":"Alarm","volume":0.35}}
{"name":"world_command","arguments":{"action":"show_text","targetName":"QuestPanel","textToDisplay":"Quest completed! +500 XP"}}
{"name":"world_command","arguments":{"action":"hide_panel","targetName":"QuestPanel"}}
{"name":"world_command","arguments":{"action":"apply_force","targetName":"Boulder","fx":0,"fy":100,"fz":50}}
{"name":"world_command","arguments":{"action":"set_velocity","targetName":"Boulder","fx":0,"fy":0,"fz":10}}
```

**Full parameter table:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `action` | string | Operation type. |
| `prefabKey` | string | Registered prefab key or primitive key for `spawn`. |
| `targetName` | string | GameObject name in the scene. |
| `x`, `y`, `z` | float | Position coordinates or vector components. |
| `fx`, `fy`, `fz` | float | Rotation degrees, force vector, or velocity vector depending on action. |
| `scale` | float | Uniform scale fallback. |
| `scaleX`, `scaleY`, `scaleZ` | float | Per-axis scale values. |
| `stringValue` | string | Scene name, search query, parent object name, HTML colour, or sound key depending on action. |
| `worldPositionStays` | bool | Parenting policy for `spawn`/`change` (default `false`: coordinates local to the parent). |
| `animationName` | string | Animation name. |
| `textToDisplay` | string | Text to display. |
| `volume` | float | Audio volume, 0–1 (default 1). |
| `itemsJson` | string | `spawn_batch` only: JSON array of up to 100 items (see [WORLD_COMMANDS.md](WORLD_COMMANDS.md)). |

**Result:** `{"Success":true,"Message":"World command 'destroy' executed successfully","Action":"destroy"}`, or
`Success: false` with the reason (for example `Missing required parameters for action 'play_sound': targetName
and stringValue are required.`).

**All public `world_command` action values:**

| Action | Description | Required parameters |
|--------|-------------|---------------------|
| `spawn` | Create registered prefab or built-in primitive | `prefabKey`, `targetName` |
| `change` | Apply optional transform/parent changes | `targetName` |
| `set_color` | Set renderer colour | `targetName`, `stringValue` |
| `destroy` | Remove | `targetName` |
| `list_objects` | List objects | optional `stringValue` |
| `spawn_batch` | Spawn up to 100 prefabs/primitives in one call | `itemsJson` |
| `list_prefabs` | List registered prefab keys | none |
| `load_scene` | Load scene | `stringValue` |
| `reload_scene` | Reload | none |
| `set_active` | Enable (show) an object; always activates | `targetName` |
| `play_animation` | Animation | `targetName`, `animationName` (or `stringValue`) |
| `stop_animation` | Stop animation | `targetName` |
| `list_animations` | List animations | `targetName` |
| `play_sound` | Play audio | `targetName`, `stringValue` (clip), optional `volume` |
| `set_volume` | Set audio volume | `targetName`, `volume` |
| `show_text` | Show text | `targetName`, `textToDisplay` (or `stringValue`) |
| `hide_panel` | Hide UI panel/object | `targetName` |
| `apply_force` | Apply force | `targetName`, at least one of `fx`, `fy`, `fz` |
| `set_velocity` | Set Rigidbody velocity | `targetName`, at least one of `fx`, `fy`, `fz` |

Removed public world actions: `move`, `rotate`, `set_scale`, `parent`, `set_transform`, `update_score`, and `spawn_particles`.

## 4. Component Command Tool (host-wired)

**Roles:** custom agents with `ComponentLlmTool` (not attached to any built-in role). The Lua
`coreai_component_*` bindings publish the same envelope where the build bindings are registered (see §2).

### Add component
```json
{
  "name": "component_command",
  "arguments": {
    "action": "add",
    "targetName": "Cube",
    "componentType": "rigidbody"
  }
}
```

### Remove component
```json
{
  "name": "component_command",
  "arguments": {
    "action": "remove",
    "targetName": "Cube",
    "componentType": "rigidbody"
  }
}
```

### Set component property
```json
{
  "name": "component_command",
  "arguments": {
    "action": "set",
    "targetName": "Lamp",
    "componentType": "light",
    "propertyName": "color",
    "stringValue": "#88aa33"
  }
}
```

### List components
```json
{
  "name": "component_command",
  "arguments": {
    "action": "list_components",
    "targetName": "Cube"
  }
}
```

**Envelope shape:**

```json
{
  "action": "add|remove|set|list_components",
  "targetName": "GameObjectName",
  "componentType": "rigidbody",
  "propertyName": "mass",
  "stringValue": "",
  "floatValue": 5,
  "boolValue": 0,
  "x": 0,
  "y": 0,
  "z": 0
}
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|:--------:|-------------|
| `action` | string | Yes | `add`, `remove`, `set`, or `list_components` |
| `targetName` | string | Yes | Existing `GameObject` name |
| `componentType` | string | For `add`, `remove`, `set` | Supported component catalog key |
| `propertyName` | string | For `set` | Supported property key for the selected component |
| `stringValue` | string | Optional | Text, HTML colour, or enum name |
| `floatValue` | number | Optional | Numeric value |
| `boolValue` | number | Optional | Boolean encoded as `0` or `1` |
| `x`, `y`, `z` | number | Optional | Vector components |

Supported `componentType` values: `rigidbody`, `rigidbody2d`, `boxcollider`, `spherecollider`, `capsulecollider`, `meshcollider`, `light`, `audiosource`, `camera`, `linerenderer`, `trailrenderer`, `textmesh`, `meshrenderer`, `particlesystem`.

`set` auto-adds the component if it is missing. Property names are case-insensitive; the full list per
component is in [TOOL_CALL_SPEC.md §5](TOOL_CALL_SPEC.md#5-component-command-tool). Examples: `rigidbody`
`mass`, `useGravity`, `isKinematic`, `linearDamping` (alias `drag`), `angularDamping` (alias `angularDrag`);
`light` `type`, `intensity`, `range`, `color`, `spotAngle`; `boxcollider` `isTrigger`, `size`, `center`;
`audiosource` `volume`, `pitch`, `loop`.

**Result:** `{"Success":true,"Message":"…","Action":"set"}`.

Lua bindings (where registered) publish the same envelope shape:

```lua
coreai_component_add("Cube", "rigidbody")
coreai_component_remove("Cube", "rigidbody")
coreai_component_set_number("Cube", "rigidbody", "mass", 5)
coreai_component_set_bool("Cube", "rigidbody", "useGravity", true)
coreai_component_set_text("Lamp", "light", "color", "#88aa33")
coreai_component_set_vector("Trigger", "boxcollider", "size", 2, 3, 2)
```

## 6. Game Config Tool (host-wired)

**Roles:** any role the host gives the tool through `GameConfigPolicy.CreateLlmTool(store, roleId)`; see
[GAME_CONFIG_GUIDE.md](GAME_CONFIG_GUIDE.md).

### Read configuration
```json
{
  "name": "game_config",
  "arguments": {
    "action": "read"
  }
}
```

### Update configuration
```json
{
  "name": "game_config",
  "arguments": {
    "action": "update",
    "content": "{\"Difficulty\": 2, \"EnemyHealthMultiplier\": 1.5}"
  }
}
```

**Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|:--------:|-------------|
| `action` | string | Yes | `read` / `update` |
| `content` | string | Yes (for `update`) | JSON object with the new values; with `UnityGameConfigStore` the keys are the ScriptableObject's field names |

`read` returns `ConfigJson` as `{"<key>": {...}, ...}` for the role's allowed keys.

## 7. Scene Tool (host-wired)

**Roles:** any agent the host gives `SceneLlmTool` (`WithTool(new SceneLlmTool())`); no built-in role has it.

`scene_tool` is a multi-function wrapper: the model calls its four functions by name. Objects are addressed by
`instanceId` (returned by `find_objects` / `get_hierarchy`), not by name.

### Find objects
```json
{
  "name": "find_objects",
  "arguments": {"searchTerm": "Enemy", "searchMethod": "name", "includeInactive": false}
}
```

`searchMethod` is `name` (substring of the object name, default) or `tag`.

### Get hierarchy
```json
{
  "name": "get_hierarchy",
  "arguments": {}
}
```

Pass `rootInstanceId` to list one object's children; omit it (or pass `0`) for the scene roots.

### Get transform
```json
{
  "name": "get_transform",
  "arguments": {"instanceId": 12345}
}
```

### Set transform
```json
{
  "name": "set_transform",
  "arguments": {"instanceId": 12345, "px": 10, "py": 0, "pz": 5, "ry": 90}
}
```

`px/py/pz` are world position, `rx/ry/rz` Euler rotation in degrees, `sx/sy/sz` local scale; omitted values
stay unchanged.

**Result:** `{"success":true,"data":…}` or `{"success":false,"error":"…"}`.

`set_transform` is separate from `world_command`; use `world_command` `change` for name-based world edits.

## 8. Camera Tool

**Roles:** Programmer (attached automatically). The chat panel can also attach it to the active chat role when
the model has vision. Hosts add it elsewhere with `AgentMemoryPolicy.AddToolForRole`.

The `camera` tool (`CoreAI.Vision.CameraLlmTool`) is a multi-function wrapper; the model calls its functions by
name: `camera_capture` (alias `screenshot`), `camera_look`, `camera_list`.

### Capture screenshot
```json
{
  "name": "camera_capture",
  "arguments": {"cameraName": "", "maxSize": 512}
}
```

**Result:** a compact JSON summary (`ok`, `summary`, `camera`, `isMain`, `width`, `height`, `format`,
`sizeBytes`, `pose`, `imageAttached`). The image itself is not in the JSON: it reaches a vision-capable model as
an image part of a follow-up user message (see [TOOL_AUTHORING_GUIDE.md](TOOL_AUTHORING_GUIDE.md#returning-images-from-a-tool)).
`camera_look` (`cameraName`, `posX`/`posY`/`posZ`, `rotX`/`rotY`/`rotZ`, `lookAt`) moves only a camera marked
agent-controllable (`CoreAiAgentCamera`); `camera_list` lists scene cameras.

## 11. Tool call error handling

### Failed calls

A failed call is returned to the model as the tool result; the model decides whether to retry.

```
Roundtrip 1: Model → {"name": "memory", "arguments": {"content": "..."}}   ← action missing
  ↓
Tool result: "Error: Tool 'memory' is missing required argument(s): action. Retry the same tool call with JSON arguments matching this schema: {...}"
  ↓
Roundtrip 2: Model → {"name": "memory", "arguments": {"action": "write", "content": "..."}}  ✅
```

`MaxToolCallRetries` (default 3) counts consecutive batches in which every call failed; when it is reached (or
the roundtrip cap is hit) the loop makes one final tools-disabled summary turn. Arguments that are missing,
`null` or of the wrong type are refused before the tool runs; an empty string reaches the tool.

### Text-shaped calls

On an endpoint with a native tool channel only the provider's `tool_calls` are executed. Without a native
channel `LlmToolCallTextExtractor` reads calls from the text for **declared** tools only:
- JSON objects `{"name": ..., "arguments": {...}}` (also `arguments_json`)
- Hermes/Qwen XML `<function=name><parameter=...>...</parameter></function>`
- Function-call syntax `tool_name(arg=...)` when the whole reply is the call
- Fenced code blocks and quoted/backticked JSON are treated as examples, not calls
- Reasoning `<think>…</think>` is filtered before the visible text is used

The legacy `{"tool": "memory", ...}` shape is not recognized.
