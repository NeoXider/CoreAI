## Часть 1. Lua-подсистема (песочница, пайплайн, биндинги)

### Сводка

Подсистема построена грамотно: MoonSharp создаётся с `CoreModules.Preset_HardSandbox | Coroutine`, поверх вырезаются опасные глобалы (`StripRiskyGlobals`), на каждую цепочку исполнения навешивается `InstructionLimitDebugger` (лимит шагов + wall-clock таймаут), envelope-конвейер защищён скользящим rate-limiter'ом, repair-цикл ограничен поколениями, исполнение принудительно переводится на main thread в `AiGameCommandRouter`. Define-гейтинг (`COREAI_HAS_MOONSHARP && !COREAI_NO_LUA`) выдержан во всех проверенных файлах. Критичных побегов из песочницы не найдено. Основные риски — ресурсные (аллокационные бомбы вида `string.rep`, не покрытые ни лимитами, ни тестами) и обходные пути исполнения Lua мимо rate-limiter'а (MEAI-тул `execute_lua`, корутины).

### Критичные находки

Не обнаружено. Прямых векторов побега (доступ к CLR/файлам/процессам/рефлексии) нет: `UserData.RegisterType` не используется нигде в runtime, в Lua попадают только `DynValue.NewCallback`-обёртки над явно зарегистрированными делегатами (`LuaApiRegistry.ApplyToGlobals`, `LuaApiRegistry.cs:28-54`), аргументы конвертируются через `ToObject()` в примитивы.

### Средние

1. **Аллокационные бомбы не ограничены памятью** — `SecureLuaEnvironment.cs:12-13`: `Preset_HardSandbox` включает модуль `string`, удаляется только `string.dump` (`SecureLuaEnvironment.cs:120-130`). `string.rep('a', 1e9)` — это *одна* VM-инструкция: `InstructionLimitDebugger.GetAction` (`InstructionLimitDebugger.cs:60-74`) сработает только на *следующей* инструкции, когда гигабайт уже выделен. Аналогично `table.concat` поверх растущей таблицы. Итог: managed-OOM / GC-фриз Unity одним envelope, в пределах rate-limit'а.
2. **Путь `execute_lua` (MEAI tool) идёт мимо rate-limiter'а** — `LuaTool.ExecuteAsync` (`LuaTool.cs:41-88`) и `LuaLlmTool` вызывают произвольный `ILuaExecutor` без `LuaGenerationRateLimiter`: лимитер интегрирован только в `LuaAiEnvelopeProcessor.Process/ScheduleProgrammerRepair` (`LuaAiEnvelopeProcessor.cs:73,144`). Production-реализации `ILuaExecutor` в runtime пока нет (все — в тестах), так что обход «спящий», но любой потребитель `LuaLlmTool` получит нелимитированное исполнение. `LUA_SANDBOX_SECURITY.md:62-73` утверждает «rate-limited end to end» — не соответствует tool-пути.
3. **`CreateCoroutine` без лимитера и суммарного бюджета** — `SecureLuaEnvironment.CreateCoroutine` (`SecureLuaEnvironment.cs:60-79`); `LuaCoroutineHandle.Resume` (`LuaCoroutineHandle.cs:39-55`) сбрасывает бюджет 10 000 шагов / 500 мс на каждый resume — бесконечная yield-корутина живёт вечно и каждый кадр съедает до 10k инструкций. `LuaCoroutineRunner` ограничивает лишь количество (64), не суммарный CPU. `Kill()` (`LuaCoroutineHandle.cs:57-90`) честно не убивает корутину — только запрещает resume; `Script` живёт до GC.
4. **`time_set_scale` — DoS уровня геймплея** — `LuaTimeBindings.cs:19`: Lua может выставить `Time.timeScale` в 0 или огромное значение без валидации; зарегистрировано по умолчанию (`AggregatingGameLuaRuntimeBindings.cs:36`). Нарушает собственное правило доки «validate every binding argument».
5. **World-биндинги не валидируют числа** — `CoreAiWorldLuaRuntimeBindings.cs:26-47,99-109`: координаты `(double)→(float)` без проверки NaN/Infinity/диапазона; громкость без капа; `coreai_world_load_scene` грузит *любую* сцену из Build Settings (`CoreAiWorldCommandExecutor.cs:378-398`). Спавн при этом корректно ограничен `ICoreAiPrefabRegistry` (`CoreAiWorldCommandExecutor.cs:98-107`).

### Низкие / наблюдения

1. `LuaExecutionGuard.Execute` (`LuaExecutionGuard.cs:36,53`) затирает debugger из `CreateScript` и делает `DetachDebugger()` в `finally` — переиспользование `Script` после guard'а останется без лимитов (сейчас скрипты одноразовые, но контракт хрупкий).
2. Post-hoc `TimeoutException` после успешного завершения (`LuaExecutionGuard.cs:38-41`) выбрасывает уже вычисленный результат; время внутри CLR-биндингов вообще не прерывается (debugger срабатывает только на Lua-инструкциях).
3. Сообщения исключений хоста утекают в модель: `LuaApiRegistry.cs:50` → `LuaAiEnvelopeProcessor.cs:112` (payload и repair-промпт). Док требует нормализации ошибок (`LUA_SANDBOX_SECURITY.md:175-182`) — не реализовано.
4. `result.ToPrintString()` без капа (`LuaAiEnvelopeProcessor.cs:90`) — мегабайтная строка целиком уходит в `JsonPayload`.
5. `GameLuaBindingsExtensibility` (`GameLuaBindingsExtensibility.cs:13`) — глобальный статический список: переживает домен при выключенном Domain Reload, протекает между тестами.
6. Парсеры payload устойчивы к мусору, но `IndexOfCommandType` может подхватить `"code"` из другого объекта дальше по тексту (риск низкий); проверка `"```Lua"` Ordinal в `ProgrammerLuaResponseParser.cs:19-22` мертва (перекрыта OrdinalIgnoreCase).
7. Repair-цикл корректно терминируется (поколение через `AiOrchestrator.cs:639,664`, сравнение с `MaxLuaRepairRetries` в `LuaAiEnvelopeProcessor.cs:116-122`); замечание: один failed-envelope съедает 2 слота лимитера из 20/60с.
8. Define-гейтинг — нарушений нет (включая inline-гейты в `CoreAssemblyEditModeTests.cs:6-8`, `AllToolCallsPlayModeTests.cs:100-111`); `versionDefines` корректны.
9. Thread-safety: main-thread маршалинг в `AiGameCommandRouter.cs:56-58` + `volatile _disposed`; `LuaGenerationRateLimiter` под локом; `InstructionLimitDebugger._steps` через Interlocked.

### Покрытие тестами

**Покрыто:** удаление `io/os/debug/load/loadfile/dofile`, `require` бросает, обходы через `_G`/`_ENV`/`rawget`; `string.dump` (напрямую и через `('x').dump`), `getmetatable('')`, `collectgarbage`, `coroutine.close`; лимит шагов, таймаут, per-resume бюджет корутин, `Kill()`, лимит 64 корутин; rate limiter (окно/eviction/отказ + интеграция «saturated → drop + skip repair»); repair-цепочка E2E с поколениями; парсеры payload.

**Не покрыто** (всё из списка «Known Attack Vectors To Test» собственной доки, `LUA_SANDBOX_SECURITY.md:163-173`):
- `string.rep` / огромные таблицы / память;
- глубокая рекурсия и parser-бомбы (`LoadString` вложенных выражений);
- `setmetatable`/`rawset` на разделяемых таблицах (`string`, `math`, `table`);
- `pcall`-поглощение лимитных исключений (`while true do pcall(...) end`);
- биндинги с NaN/Infinity/экстремальными числами/огромными строками;
- путь `LuaTool`/`execute_lua` против реального `SecureLuaEnvironment`;
- регресс-тест на отсутствие `package`.

### Рекомендации (Lua)

1. Обернуть `string.rep` капом длины (аналогично `string.dump` в `StripRiskyGlobals`); рассмотреть прочие аллокаторы.
2. Прокинуть `LuaGenerationRateLimiter` в `LuaTool` (или будущую production-реализацию `ILuaExecutor`) либо явно задокументировать обход; поправить «end to end» в `LUA_SANDBOX_SECURITY.md`.
3. Валидация числовых аргументов в world-биндингах (NaN/Inf/диапазон, кап громкости), whitelist сцен для `coreai_world_load_scene`, кап/удаление `time_set_scale`.
4. Суммарный бюджет жизни корутины (total steps across resumes) в `LuaCoroutineHandle`.
5. Обрезать `ToPrintString()` и нормализовать тексты ошибок перед публикацией в payload/repair-промпт.
6. Добить тесты по списку выше: rep-бомба, рекурсия, pcall-поглощение, NaN-аргументы, `package`.

## Часть 2. Общий аудит проекта

### Сводка

Проект в хорошем состоянии: ядро `CoreAI.Core` действительно изолировано от Unity (`noEngineReferences: true`, ни одной ссылки на `UnityEngine` в коде), слоистость asmdef корректная и ацикличная (Core ← Source ← Editor/Tests/ExampleGame). Файловые хранилища памяти агентов защищены: `SemaphoreSlim`-гейт, атомарная запись tmp+`File.Replace`, offload в thread pool с inline-fallback для WebGL. Magic strings ролей в продакшен-коде вынесены в `BuiltInAgentRoleIds`/`RoleId`. API-консистентность образцовая (`AskAsync` primary / `AskWithCallback` convenience / `Ask` obsolete, закреплено тестом). Критичных дефектов нет; есть средние по асинхронности/логированию и шероховатости CI.

### Критичные находки

Не обнаружено.

### Средние

1. **Копипаст-лог: одно сообщение на четыре исхода** — `LlmUnityAutostartEntryPoint.cs:60-99`: `"LLMUnity: autostart status changed."` логируется при «уже запущен», исключении из `agent.Start()`, таймауте warmup, `llm.failed` и успехе. Диагностика по логам невозможна.
2. **`AskWithCallback` вызывает callback не на main thread** — `AgentConfigExtensions.cs:118-121`: после `ConfigureAwait(false)` продолжение может выполниться в thread pool — обращение к Unity API из `onDone` даст исключение/UB. Нужен маршалинг на main thread в Unity-слое либо явное предупреждение в doc-комментарии.
3. **Потеря stack trace в catch-логах** — системный паттерн `ex.Message` без `ex`: `FileConversationSummaryStore.cs:125,180,232`, `AgentConfigExtensions.cs:125`, `CoreAIGameEntryPoint.cs:112`, `LlmUnityAutostartEntryPoint.cs:70` и далее.
4. **CI: хрупкий sed для define** — `.github/workflows/ci.yml`, шаг «Strip MoonSharp»: `sed 's/: DOTWEEN$/...'` молча перестанет работать при изменении соседних defines; проверка не падает при нуле совпадений — job «no-lua» может тихо стать дубликатом «moonsharp». Добавить `grep -q COREAI_NO_LUA ... || exit 1`.
5. **CI: secrets недоступны на PR из форков** — `UNITY_LICENSE/EMAIL/PASSWORD` пустые для форков → оба matrix-джоба упадут на лицензировании. Если внешние PR ожидаются — skip-условие или `pull_request_target` (с осторожностью).
6. **`SemaphoreSlim _gate` нигде не Dispose** — `FileConversationSummaryStore.cs:27`, `FileAgentMemoryStore.cs:66`: классы владеют `IDisposable`-семафором, но сами не `IDisposable`. Для синглтонов некритично, при пересоздании scope — утечка handle.

### Низкие / наблюдения

1. Эвристика по подстрокам ролей в ядре — `LlmConversationalRolePolicy.cs:34` (`r.Contains("chat") && !r.Contains("merchant")`); роль `"MerchantChat"` классифицируется неочевидно. Аналогично `OfflineLlmClient.cs:61,81` (offline-заглушка, допустимо).
2. Коллизии имён файлов после санитизации roleId — `FileConversationSummaryStore.GetPath`: `"A/B"` и `"A_B"` дают один файл `A_B.json`. То же в `FileAgentMemoryStore`.
3. `async void TestConnection` в editor-коде (`CoreAISettingsAssetEditor.cs:924`) — исключение вне try уронит editor loop; остальные `async void` обёрнуты в try/catch целиком.
4. Пустые catch без комментария намерения: `UnityMainThreadLlmAsyncMarshaler.cs:118,135`, `RefreshOnUnauthorizedDecorator.cs:193`, `MeaiLlmClient.cs:1050,1098`, `MeaiOpenAiChatClient.cs:998,1426` (остальные — осмысленные best-effort с комментариями).
5. CI: `unity-test-runner` задан `checkName`, но без `githubToken` check-run не публикуется.
6. CI: проверка покрытия sandbox-тестов через `grep -o | wc -l` по XML — рабочая, но порог «10 вхождений» эвристический; точнее парсить `testcase`-узлы.
7. Magic strings ролей в тестах (десятки мест) — допустимо, но `BuiltInAgentRoleIds.*` сделал бы их устойчивыми к переименованию.
8. `ConfigureAwait`-дисциплина в ядре хорошая (45 использований); батч-исполнение тулов последовательное и корректное.
9. `CoreAI.Core.asmdef` ссылается на `MoonSharp.Interpreter` — контролируется через `versionDefines`/CI-матрицу, корректно.
